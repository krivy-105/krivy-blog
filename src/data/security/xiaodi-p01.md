## 二、核心知识点

### 1. 网站搭建的最小流程（02:00-09:00）
```
购买服务器(阿里云/腾讯云，按量付费几毛/小时) + 购买域名
→ 服务器装中间件（Windows→IIS 为例）
→ 上传网站源码（演示用Zblog，ASP版）
→ IIS"添加网站"：物理路径指向源码目录 + 绑定域名
→ 域名解析添加A记录：www → 服务器公网IP
→ TTL生效（现在很快，以前10分钟）→ 访问上线
```

### 2. DNS解析与子域名（07:00-14:00）
- A记录：`www.xxx.com → IP`；再添一条 `xiaodi.xxx.com → 同一IP` 也能访问
- **坑点**：IIS绑定只绑了 www，访问未绑定的子域名会直接落到IP默认站点 → 绑定和解析是两回事
- 由此引出 **子域名模式**：`bbs.xxx.com`跑Discuz论坛、`oa.xxx.com`跑通达OA——**一个域名背后是N套程序**

> ⚔️ 安全思维：为什么信息收集要收集子域名？——因为任何一套程序爆洞，整个目标都算拿下。

### 3. 三种常规搭建模式（14:00-18:00）★本课灵魂
| 模式 | 区别 | 安全含义 |
|---|---|---|
| **子域名模式** | 不同host头 → 不同源码 | 子域名收集=扩大攻击面 |
| **端口模式** | 80一套程序、88/8080另一套 | **为什么做端口扫描**——域名相同，程序不同=两个攻击点 |
| **目录模式** | `xxx.com/blog/`下再放一套源码 | 目录爆破也能发现新目标 |

> ⚔️ 核心结论：**判断"网站"不看域名，看程序。渗透测试针对的是程序，不是域名。**

### 4. 其他搭建形态（18:00-24:00）
- **集成软件**：宝塔、phpStudy——鼠标点几下全装好
- **Docker容器**：拉镜像直接起站
- **分配站**：平台分配二级域名给用户（如博客平台）→ 打它=打整个平台，且平台化运维安全系数更高
- **大厂自建**：腾讯阿里自有机房自研程序——**不用开源源码**（开源人人可见=安全系数最低）

> ⚔️ SRC预判：看到目标名字→脑补它用什么源码→判断你能不能拿到源码→决定走黑盒还是白盒（代码审计）路线。

### 5. 中间件配置受限实战（IIS演示，28:00-37:00）★攻击+防御双视角
小迪模拟了两轮：
1. **攻击者**：上传webshell(1.jsp) → 哥斯拉(Godzilla)连接成功，拿到网站控制权
2. **管理员防御**：
   - **NTFS目录权限**：给webshell所在目录加"拒绝" → 连接直接失败（"权限无效，访问被拒绝"）
   - **脚本执行权限**：读取/写入/执行三项——不给执行权限，后门就是废的；但**只能锁图片等静态目录**，锁脚本目录网站直接挂 → 防御与业务天生矛盾
   - **Windows身份验证**：替换匿名认证 → 访问弹登录框；但这玩意绕不过（有主机账密就直接登主机了），**碰到只能放弃换攻击点**

> ⚔️ 这段回答了新手最常见的疑问："我上传的Shell为什么连不上？"——大概率就是这些配置锁死了。

### 6. 源码结构与数据库配置文件（43:00-48:00）
- **找数据库配置文件的规律**：看目录/文件名——`data/`、`include/`、`conn.*`、`config.*`、`app.config`、`c_option.php` 这类数据库相关英文命名
- 配置内容四要素：**主机、用户名、密码、库名**
- Access库（小型，类似Excel，无账密，Office直接打开）vs MySQL/SQLServer（要账密）
- 演示：后台发一篇文章 → 直接打开数据库文件看到那条记录 → **管理员账号密码（MD5加密）也躺在里面**

### 7. 站库分离（49:00-66:00）★重点
```
本地模式：源码+数据库同一台服务器 → 拿下Web≈拿到数据
站库分离：数据库单独一台服务器 → 配置文件里写数据库IP/账密
云RDS：  直接买云数据库（不装操作系统）→ 安全组IP白名单
         → 即使拿到账密也连不上（必须从指定网站服务器连）
```
- 演示：Zblog不支持分离 → 换.NET源码，`app.config`里写数据库IP 8.218.x.88 → 删掉数据库网站立刻崩（"数据库连接问题"）
- **OSS对象存储**：上传文件全丢进OSS → 上传的webshell没有解析执行环境 → **上传漏洞直接失效**

> ⚔️ 安全趋势：新架构（RDS+OSS+WAF）让大量传统漏洞"天然不存在"——这就是为什么渗透越来越卷，也是为什么信息收集要先判断目标架构。

### 8. 源码可见性（66:00-73:00）
- 开源**可看**：直接读 → 白盒审计
- 开源**不可看**：
  - 加密：源码加密平台（不影响功能）
  - **语言特性**：Java编译成class、.NET编译成dll → 拿到源码也是字节码 → 要用**反编译工具**（如dnSpy）还原
- 拿不到可读源码 = 白盒审计路线断了

### 9. 源码目录命名规律（73:00-74:00）
```
admin→后台  bin→执行程序  database→数据库  image→图片
js→前端脚本  member→会员  template→模板  uploadfiles→上传文件
```
> 拿到shell后按命名规律快速定位高价值文件。

### 10. 路由访问（74:00-80:00）★新手必踩的坑
- **常规**：URL路径 = 目录对应（绑定根目录后逐层往下请求）
- **非常规**：Java/Python框架有**路由配置**——文件明明在目录里，按常规URL请求不到（演示：Java站点里 `web-inf` 下文件直接访问404）
- **经典翻车场景**：上传了webshell，文件确实存在，但按路径死活请求不到 → 该站点是路由型，必须按它特有的路由规则构造URL

> ⚔️ 这就是后面要学"安全开发"的原因：自己写过路由，才知道漏洞payload的URL该怎么构造、触发点在哪。

### 11. MIME解析规则（83:00-86:00）
- 中间件的MIME类型决定文件是**执行/显示/下载**
- 把asp映射成image/png → asp后门被当图片 → 不执行 → 后门废了
- "为什么访问php变成下载"这类疑问，答案都在MIME配置里
