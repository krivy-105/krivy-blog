**一句话总结**：用 Charles、Fiddler、Burp Suite 三款 HTTP(S) 抓包工具 + Proxifier 转发联动，打通浏览器、APP、小程序、PC 应用四个方向的抓包点位差异——记住三句话：**HTTPS 必装证书、Burp 必配代理、没有代理入口的程序用转发**。

## 0. 总纲与边界（00:10-02:30）
- 本集只抓 **HTTP/HTTPS**：游戏等走私有协议的数据这三款工具抓不到（23:00-23:30、78:00-78:30）。
- 四个对象：WEB（浏览器）、APP（模拟器）、小程序（PC 微信）、PC 应用（C/S，例：腾讯文档）。
- 工具：Charles（默认端口 8888，自动设系统代理）、Fiddler（8888，自动系统代理）、Burp Suite（8080，须手动配代理）、Proxifier（按进程强制走代理的转发工具）。两两同开会撞 8888 端口（12:06-12:24）。
- 下节课：抓其他协议（预告 Wireshark、科来类工具，01:24、90:43）。

## 1. HTTPS 抓包为什么先装证书（02:45-11:30）
原理：抓包工具夹在客户端与服务器中间当"中间人"，HTTPS 流量加密，工具必须持有一张自己的 CA 根证书并让客户端信任，才能解密双向数据；不装证书只能看到密文。验收标准（11:15-11:30）：装完后能抓到 HTTPS 包即成功。

**导证书入口**
- Charles：Help → SSL Proxying → Save Charles Root Certificate。
- Fiddler：Tools → Options → HTTPS → Actions → Export Root Certificate to Desktop。
- Burp：Settings → Import / export CA certificate 导出。

**装进两个环境**
1. 安卓模拟器：证书拖入模拟器"共享目录"自动同步 → 设置 → 安全 → 从 SD 卡安装 → 输锁屏密码 → 命名安装（04:30-06:25）。
2. 本地 Chrome：设置 → 安全 → 管理设备证书 → 受信任的证书颁发机构 → 导入（09:50-10:55）。
- 坑：Burp 证书是 DER 格式模拟器不认 → 模拟器浏览器访问 `http://本机IP:8080` 下载后改后缀 `.cer` 再装（07:30-09:35）。

⚔️ 安全思维：这就是一次中间人攻击（MITM）标准流程——渗透中给目标机器装一张 CA 即可解密其 HTTPS 流量；反过来 APP 做"证书校验（SSL Pinning）"防的就是这一手。

## 2. WEB/浏览器抓包（11:32-23:30）
- Charles、Fiddler 开箱即抓（自动系统代理）；Fiddler 需勾：Options → HTTPS → Capture HTTPS CONNECTs、Decrypt HTTPS traffic；抓外部设备选 "...from remote clients"（12:14-12:48、25:00-25:09）。
- Burp 配代理：Windows 设置 → 网络和 Internet → 代理 → 手动 `127.0.0.1:8080`；**"请勿对以下地址使用代理服务器"例外列表要清空**，否则本地靶场抓不到（16:02-16:58）。
- 演示（17:02-18:08）：Burp 开 Intercept → 刷新 xiaodi8.com → 请求卡住 → 老师把路径改为后台地址（如 /admin/login.php）→ Forward 放行 → 浏览器跳到登录页；Drop=丢弃不发。说明：拦截的包可改可放，实时改包成立。
- 原理（18:09-19:59）：工具本地监听端口，浏览器流量经它=多个中间人。**设了代理必须开着工具**，否则流量到代理就断、网站打不开（新手常见事故）。
- 按域名筛选只看目标站（22:00-22:37）。

⚔️ 安全思维：抓包产出=URL/参数/接口清单，是测 SQL 注入、未授权、信息泄露的第一步；"拦截-改包-放行"就是手工渗透的基本动作。

## 3. 模拟器/APP 抓包（23:30-45:00）
关键认知：模拟器=一台独立设备（有自己的 IP），抓它等于在本机抓另一台机器的流量，**必须给它配代理**。
- 模拟器代理（27:07-27:59）：长按 WiFi → 修改网络 → 高级选项 → 代理手动 → 服务器填**本机出口网卡 IP**（先 `ipconfig`，选以太网/WiFi 的 IP，别选 VMware 虚拟网卡）→ 端口 8080。
- Burp 监听要加网卡地址：Proxy → Options → Add 绑定 `192.168.1.6:8080`，流量从哪块网卡进来就听哪个，只听 127.0.0.1 抓不到（34:41-35:40）。
- 流程（28:09-29:19）：先用模拟器浏览器访问 xiaodi8.com/百度，确认 HTTP+HTTPS 都能抓，再开 APP，别跳步。
- 定位接口（38:01-39:35）：Burp 开拦截 → 点 APP 某功能 → 卡住的包就是它 → 放行后页面才出结果即验证；登录包可见账号与密码密文（39:08）。
- 杂包判断（40:00-40:30）：版本更新、推送（腾讯域名）等莫名包，看域名忽略。
- Fiddler 抓到的 HTTPS 内容仍显乱码（压缩/编码），分析回 Burp 做（33:50-34:18）。

⚔️ 安全思维：APP 测试=接口测试；抓不到包先怀疑"私有协议或代理检测"，别死磕工具。

## 4. 小程序抓包——转发联动（45:00-63:00）
痛点：微信没有代理设置入口；开系统代理会让微信全部流量走代理，消息都发不出（48:28-49:52）。
- 方案1 Charles→Burp 转发（41:04-44:20）：Charles → Proxy → External Proxy Settings（带外代理设置）→ Web/HTTPS 都指向 `127.0.0.1:8080`，Burp 直接收包；同机填 127.0.0.1，异机填对方 IP。验证（50:48-52:13）：开拦截点小程序功能，包卡住、放行页面才有反应。
- 方案2 Proxifier 按进程转发（52:24-62:30）：① Proxy Servers 添加 `127.0.0.1:8080`（HTTPS）；② Proxification Rules 建规则，进程填 `WeChat*.exe`（* 为任意字符）→ 动作选该代理 → 仅微信走 Burp，系统流量不受影响；③ 规则可再叠加目标主机/域名、端口条件（53:07-54:37）。
- 插曲（55:00-59:50）：系统代理是 Charles 自动开的，排查"为何还能抓到"耗了几分钟——用完记得关代理。

⚔️ 安全思维：Proxifier 思路=给"没有代理设置的程序"强制指路，内网做流量转发/审计同款；防御方"代理检测"是 APP 加固常规手段，绕过留到 APP 专项。

## 5. PC 应用（C/S）抓包（63:00-77:40）
以腾讯文档为例：
- Fiddler/Charles 直接抓到验证码、登录接口（63:56-65:40）；Burp 开系统代理也能抓，登录包可见 `u=账号`、密码密文（66:18-67:10）。
- Fiddler "任意进程"抓包的坑（67:36-69:20）：高权限程序（360、腾讯系）把进程权限锁死防逆向，工具拿不到所有权就拦截不了，只对小应用有效。
- Proxifier 兜底（69:40-73:30）：任务管理器查到腾讯文档主进程名（如 TencentDocs.exe，以实际为准）写进规则 → 不开系统代理也照抓 → 拦截登录包、放行看响应。
- 包太多：先清空，开拦截再触发目标操作（76:00-77:30）。

⚔️ 安全思维：C/S 同样先抓登录/鉴权接口；密码是密文，就要逆它的加密算法再构造请求（102:00-103:40）。

## 6. 局限与预告（77:40-81:30、90:40-91:20）
- 只管 HTTP/HTTPS，其他协议一律抓不到；有代理检测/证书校验的 APP 一开代理就断网——绕过在 APP/小程序专项章节讲。

## 7. 为什么要抓包（102:00-103:40）
① 找目标（域名/IP/URL）；② 拿参数测漏洞（SQL 注入、未授权、信息泄露）；③ 拿数据做逆向，分析算法/JS 后构造越权请求。
