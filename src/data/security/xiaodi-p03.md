## 一、一句话总结这节课

**给网站套上5种"云时代装备"（WAF/CDN/OSS/反向代理/负载均衡）逐一演示——每种装备都会让一类传统攻击手法直接失效，同时带来新的攻击面；信息收集时先识别目标用了哪种架构，才知道哪些测试是白费劲。**

## 二、核心知识点

### 1. WAF：网站应用防火墙（00:43-08:38）
- 全称 Web Application Firewall，部署在网站前面的安全防护产品，类比电脑杀毒软件
- **分类**：硬件型（企业机房盒子）、软件型（装在服务器上）、云WAF（阿里云/腾讯云厂商提供）——企业以硬件和商业产品为主，个人多用免费的软件型
- **攻防双视角演示（IIS+免费WAF）**：
  1. 防护关闭：访问 1.jsp 后门正常 → 菜刀类工具成功连接，正常通讯
  2. 开启防护：访问后门直接提示"**禁止脚本的访问，如有疑问请和管理员联系**" → 工具连接失败
- **绕WAF的真相（老师大实话）**：
  - 绕WAF本质是钻空子，**大部分商业产品（安恒/绿盟/深信服）基本绕不过**，能绕的都是防护差的产品
  - "要是随便就能绕过，这产品还有什么存在的意义？"
  - 遇到好WAF → **换攻击点**，别死磕

> ⚔️ 安全思维：Webshell连不上、payload全被拦，第一反应应该是"这站前面有没有WAF"，而不是怀疑自己payload写错了。判断WAF存在是信息收集的必查项。

### 2. CDN：内容分发网络（08:37-28:34）★你的数通主场
- 原理：内容分发服务，在全球/全国布节点，**用户就近访问**（湖北的站在湖北快，美国用户走美国节点）
- **实操全流程（阿里云CDN）**：
  1. 前提：**域名必须备案**（老师专门找群里要了个备案域名来演示）
  2. CDN控制台添加加速域名 → 选加速区域（仅中国内地/全球/全球不含内地）
  3. 设置源站 = 真实服务器IP（47.x.x.x）
  4. 等配置生效（3-10分钟）→ 去DNS处把域名**CNAME**指向CDN分配的加速域名
  5. 验证：超级ping多地区检测——广东佛山解析到东莞节点、福建福州解析到泉州节点，**各地拿到的IP全不一样**
  6. 对照实验：网站目录放个1.txt证明真实源站还是自己那台——CDN只当"前台接待"
- **安全影响（核心）**：ping/查域名拿到的全是节点IP，**真实IP被隐藏** → 端口扫描、漏洞测试全打在节点上=打了个寂寞

> ⚔️ 安全思维：这就是为什么信息收集有一整块"**找真实IP**"的专题（后面课程会讲）。你数通学过CNAME和Anycast，这部分理解零成本——重点记住"测站前先判断开没开CDN"。

### 3. OSS：对象存储服务（28:32-53:30）★本集安全含金量最高
- 原理：文件单独存储到云端对象存储，网站只存代码不放文件；图片/视频走OSS专线加载，速度更快且便于管理
- **实操（网盘源码+阿里云OSS）**：
  1. 一个exe直接运行的私有云盘源码，跑在 5212 端口
  2. 存储策略选阿里云OSS：填 bucket 名称、外网节点、**AccessKey(AK)** → 启用
  3. 上传图片 → 文件不落网站目录 → 落到 OSS bucket 的 uploads/日期 目录里
- **安全影响①（好的一面）**：上传的文件到了OSS——**OSS只存储不解析脚本**，传个webshell上去访问=下载/空白，代码根本不执行 → **上传漏洞被OSS天然修死**
- **安全影响②（坏的一面）**：配置时要填 **AccessKey**——这是阿里云资源的访问密钥，**泄露了AK=能管理该账号下所有OSS乃至云产品** → 老师演示完立刻把AK关掉（"有我这个K就能进我阿里云"）→ 这叫**云安全/产品安全**，是传统漏洞之外的新攻击面

> ⚔️ 安全思维：测上传漏洞前先确认文件是不是传到OSS去了——是就直接跳过这项（测了也没意义）；反过来，目标源码/配置里泄露的AccessKey是比webshell更值钱的入口。

### 4. 反向代理 vs 正向代理（53:31-65:01）
- **一句话区分**：正向代理=客户端的代理（你自己翻墙访问别人，服务器啥都没干）；反向代理=服务端的代理（服务器主动把流量交给另一台机器，你访问那台机器就等于访问它）
- **危险演示（宝塔+Nginx反代）**：
  1. 建站 xiaodi.z.com → 添加解析记录 → 能正常访问
  2. 网站设置→反向代理→目标地址填 **www.baidu.com** → 再访问 xiaodi.z.com，**显示的是百度首页**，点啥都是百度
  3. 进阶：高级功能设代理路径——访问 `/b` 目录 → 跳到 **哔哩哔哩**（主站反代百度、b目录反代B站，想怎么配就怎么配）
  4. （老师还现场演示了反代某学校网站后台时路径没带上的翻车现场，改"目标地址+内容地址"才成功）
- **安全影响（重要）**：你打开的"目标网站"可能是反代出来的**别人的东西**——"你在百度上面咔咔乱测，测了个毛，跟目标站毫不相干"
- 正向代理对测试**没有影响**（它只动客户端，服务器端什么都没配置）

> ⚔️ 安全思维：测站前先确认"我看到的界面是它自己的东西还是反代出来的"——否则从头到尾在给百度做免费渗透测试。反代和跳转、转发流量的区分后面内网课还会再展开（正向/反向连接）。

### 5. 负载均衡（66:05-73:01）
- 原理：任务分摊到多个操作单元执行；两大价值——提高访问效率 + **容灾**（老师举例：服务器在四川，汶川地震没了怎么办？多台备着，一台挂了下一台顶上）
- **实操（宝塔Nginx负载均衡）**：
  1. 准备两台服务器（81端口各跑一个不同内容的站点）
  2. 配置文件里定义 upstream（负载均衡名）+ 两个 `IP:端口` 节点，根路径触发该策略，名字要上下对应
  3. 刷新网站 → 一次显示站点A、再刷显示站点B → **两台同时提供服务**
  4. 加 `weight` 权重（4和1）→ 多次刷新才轮到权重低的 → 以权重为主
- **安全影响**：目标背后是3、4、5台服务器，**每一台内容一致但机器不同**——"你说你是拿下一台就算了，还是拿多台？"

> ⚔️ 安全思维：负载均衡目标要做**多机测试**——你测到的A机有漏洞不代表B机也有，反之亦然；拿下A机后还要横向确认B/C机的配置差异。

### 6. 三天架构课的总结（73:02-83:36）
老师带着画了思维导图，两张图合起来是P1-P3全部搭建方案：

| 架构 | 作用 | 对安全测试的影响 |
|---|---|---|
| WAF | 拦截攻击 | 常规payload被拦，绕不过就换点 |
| CDN | 就近加速 | **隐藏真实IP**，扫描测试打在节点上 |
| OSS | 文件单独存储 | **上传漏洞修复**；新隐患：AccessKey泄露 |
| 反向代理 | 服务端流量转发 | **测到的是假站**，与真实应用无关 |
| 负载均衡 | 分摊+容灾 | **多台服务器**，台台都要测/都要拿下 |

- 核心思想（老师反复强调）：**架构决定测试思路**——"你连文件传到OSS都不知道，还测什么上传？所有这些都是为后面信息收集扫清障碍"
